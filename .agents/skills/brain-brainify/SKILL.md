# brain-brainify — 씨앗 깊이 키우기 (`seed → bloom`)

> **핵심 원칙:** 새 파일을 만들거나 폴더를 옮기지 않습니다. 기존 노트를 질문으로 파고들어 **제자리에서 더 깊고 정확하게** 보강합니다.

## ⚙️ 경로 설정 (`Kobot-AI-OS-Starter`)

| 이름 | 설정값 | 설명 |
|---|---|---|
| `TOPICS_DIR` | `Ark/` | 대상 노트가 있는 내 주제 방들 (`Blocks/` 제외) |
| `TEMPLATE` | `_TEMPLATES_/BRAIN-Note.md` | 섹션 구조 기준 (`요약` · `1. 개요` · `2. 생각`) |

---

## 언제 사용하나요
- `seed`로 심어 둔 노트가 1~2줄로 얇거나 모호한 부분이 있을 때
- 자료를 다시 읽으며 새로운 반론·예외 조건·실무 적용 포인트가 떠올랐을 때
- 개념 이해에 빈틈(오개념)이 없는지 AI의 질문으로 검증받고 싶을 때

---

## 에이전트 실행 절차

### 1. 대상 노트 읽기
- 사용자가 지정한 `Ark/` 내 노트를 먼저 끝까지 읽고 `요약` · `1. 개요` · `2. 생각(Resonate / Amplify)` 내용을 파악합니다. (`3. 활용`은 `/brain-connect` 영역이므로 건드리지 않습니다.)

### 2. 섹션별 깊이 & 정확성 진단
각 섹션을 평가해 보고합니다:
- 🔴 **Thin:** 1~2문장 또는 키워드만 있음
- 🟡 **Adequate:** 3~5문장으로 맥락이 있으나 수치·반례·내 관점이 부족함
- 🟢 **Deep:** 단락 단위로 근거·예시·한계까지 명확히 정리됨

논리적 빈틈이나 확인이 필요한 오개념 의심 지점이 보이면 함께 짚습니다.

### 3. 가장 얕은 섹션부터 보강 질문 (한 섹션씩 진행)
- **`1. 개요` 보강:** "이 개념을 어떤 구체적 문제(예: 코드 버그, 스터디 질문) 때문에 보게 되셨나요? 기존에 알던 것과 무엇이 달랐나요?"
- **`2. 생각 — Resonate` 보강:** "이 명제에서 가장 결정적인 조건이나 핵심 파라미터 1~2개를 꼽으면 무엇인가요?"
- **`2. 생각 — Amplify` 보강:** "이 원리가 성립하지 않는 예외 조건(반론)은 무엇일까요? 실제 프로젝트나 발표에 적용할 때 주의할 점은 무엇인가요?"

### 4. 제자리 통합 업데이트
- 사용자 답변을 받아 해당 섹션만 확장·재구성합니다. (기존 문장 임의 삭제 금지, 단 합의된 오개념은 교정)
- 핵심 명제가 더 날카로워졌다면 `## 요약`도 함께 다듬습니다.

### 5. 메타데이터 갱신 (`0_Me/_FRONTMATTER_REGS.md` 준수)
- `요약` · `1. 개요` · `2. 생각(R/A)`이 모두 🟢 Deep 수준이 되면 `stage: seed` → **`stage: bloom`**으로 변경합니다. (`status`는 `draft` 유지, `tags:`에 메타 태그 추가 금지)

### 6. 완료 보고
- 보강 결과(🔴/🟡 → 🟢)와 `stage: bloom` 전환 여부를 보고하고 다음 걸음(`/brain-connect`)을 안내합니다.

---

## 절대 하지 않는 것
- ❌ 사용자 답변 없이 빈 섹션을 AI 추정으로 채우기
- ❌ 기존 작성 문장을 임의로 덮어쓰기
- ❌ `3. 활용(Integrate / Navigate)`을 이 단계에서 미리 채우기
- ❌ 새 파일을 복제하거나 폴더 이동하기
- ❌ `status: bloom`처럼 5규약 `status` 필드를 오염시키기
