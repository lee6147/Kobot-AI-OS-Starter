# kobot-onboard — 조원 맞춤형 AI OS 자동 온보딩

> **목적:** 조원이 긴 강의 교안 `.md` 파일을 일일이 읽지 않아도, **대화 4단계만으로 내 전공·역할에 맞춘 폴더 구조, `0_Me/` 정의문, 5축 태그, `Archive/wiki/index.md`**를 자동으로 구축합니다.

## ⚙️ 경로 설정 (`Kobot-AI-OS-Starter` 전용)

| 이름 | 설정값 | 역할 |
|---|---|---|
| `STATUS_FILE` | `0_Me/ONBOARDING_STATUS.md` | 온보딩 완료 여부(`completed: false → true`) |
| `REGS_FILE` | `0_Me/_FRONTMATTER_REGS.md` | 5규약 및 본인 맞춤형 `tags` 허용 목록 |
| `TEMPLATES_DIR` | `_TEMPLATES_/` | `Before-Diagnosis`, `5S-자가진단 워크시트`, `BRAIN-Note`, `Daily-Note`, `Daily-Reflect`, `Source-Article`, `Template_Project`, `Template_Task`, `Template_Weekly-Review`, `자가진단-3축`, `30-90-365 체크리스트`, `Web-Clipper/*.json` 4종 |
| `ARK_DIR` | `Ark/` | 맞춤형 주제 방 3~5개가 생성될 자리 (`Blocks/` 유지) |
| `WIKI_DIR` | `Archive/wiki/` | `Ark/`와 1:1로 맞춘 위키 카테고리 폴더 및 `index.md` |

## 에이전트 실행 절차

### 1. 상태 확인
- `0_Me/ONBOARDING_STATUS.md`의 진도와 대화 체크포인트를 읽고 `.agents/skills/kobot-guide/SKILL.md` §1-B의 저장·재개 절차를 적용합니다. `completed: false`이면서 `승인됨`이면 기존 승인안을 확인해 §4의 누락된 저장·검증부터 이어갑니다. `대기`일 때만 승인 질문을 다시 보여주고, 아직 제안 전이면 미응답 인터뷰부터 이어갑니다. 이미 `true`이고 사용자가 세팅 변경을 요청했다면 *"이미 온보딩이 완료되어 있습니다. 주제 방이나 역할을 수정할까요?"*라고 묻고, 단순 진도 재개라면 기존 세팅을 보존하고 가이드로 돌아갑니다.

### 2. 4단계 1:1 인터뷰 (한 번에 1~2문항씩 질문 — 몰아 묻기 금지)
*(선행 체크: `0_Me/Before-Diagnosis.md`의 초안과 완료본(`status: organized`)을 구분해 읽습니다. 기존 `0_Me/MAAP.md`가 있으면 함께 확인하고, 진단의 MAAP·하네스 우선순위, 역할·프로젝트, 지식 영역과 상태 파일의 인터뷰 답변을 재사용합니다. 답이 엇갈리면 어느 내용을 쓸지 확인합니다. 비어 있는 필수 항목만 한 번에 1~2개 묻고, 파일 유무로 Stage 0 완료를 판정하지 않습니다.)*

각 답변은 상태 파일의 `### 온보딩 인터뷰 답변`에, 다음 질문은 대화 체크포인트에 바로 저장합니다. 개념 질문은 가이드의 **쉬운 설명 → 이해 확인 → 보류한 실습 복귀** 순서를 따릅니다.

사용자가 부담 없이 답하도록 2턴에 나누거나 한 항목씩 묻습니다:

1. **기본 프로필과 AI 역할:** 이름 또는 닉네임과 AI에 맡길 역할·말투·전문 분야를 확인합니다.
2. **L1·L2·L3 맥락:** 현재 목적(Meaning), 올해 역할(L2) 2~3개, 이번 학기·분기 프로젝트(L3) 1~2개를 확인합니다. L1은 조원이 직접 말한 경우에만 기록하고, 미응답이면 비워 둡니다. 현재 목적이나 프로젝트에서 L1을 추론하지 않습니다.
3. **핵심 지식 영역(3~5개):** "내가 남에게 자주 설명하거나 앞으로 계속 파고들 주제 3~5개는 무엇인가요? (기본 포함 추천: `기록-인사이트`, `독서`)"
4. **현재 기록 습관(5S 체크):** "평소 공부하거나 AI와 대화할 때 가장 아쉬운 점은 무엇인가요? (예: 대화만 하고 문서로 안 남김, 정리 없이 쌓아만 둠)"

개인화에 필요한 `Assets`(AI가 참조할 자료와 실제 볼트 내 경로), `Actions`(AI가 먼저 실행할 루틴 1개)는 기존 답에서 확인합니다. 자료나 루틴이 아직 없다면 그 상태를 확인하고, 경로나 행동을 임의로 정하지 않습니다.

### 3. 맞춤형 볼트 구조 제안 (승인 먼저)
답변을 바탕으로 폴더·태그·프로젝트·기록 습관과 지침 변경을 한 제안으로 제시해 **사용자 확인·승인**을 받습니다.
- **`Ark/` & `Archive/wiki/` 1:1 폴더 목록 (3~5개):** 조원이 쓴 단어를 그대로 폴더명으로 살림
- **소문자 `tags` 3~5축 매핑:** 예) `ros2` (`ROS2-자율주행/`), `cpp` (`C++-알고리즘/`), `ai` (`AI-활용법/`), `record` (`기록-인사이트/`), `reading` (`독서/`)
- **첫 `Lab/Projects/` 후보 1개**
- **5S 진단 한 줄 처방**
- **파일별 생성·갱신 내용 및 루트 지침 미리보기** — `AGENTS.md`·`GEMINI.md`·`CLAUDE.md` §1에 반영할 정확한 문구를 보여줍니다. 조원 이름·역할·목적, AI의 역할·말투·전문 분야, 참고할 자료 경로(Assets), 우선 루틴(Actions)을 포함합니다. 새 말투와 충돌하는 기존 문구가 있으면 바꿀 줄까지 함께 제시합니다.

제안 내용, 파일별 변경 내용, 루트 지침 미리보기를 상태 파일의 `### 승인 대기 제안`에 보존하고 `승인 상태: 대기`로 기록합니다. 이 제안에 대한 한 번의 승인으로 제시한 구조와 지침 문구를 적용합니다. 새 채팅에서도 같은 제안에 대한 실행 승인을 기다립니다. `"이해했어요"`만으로 생성하지 않습니다.

### 4. 승인 후 자동 스캐폴딩 실행
기록된 제안에 사용자가 명시적으로 실행을 승인하면 아래 작업을 실행합니다. 중간에 끊겼다면 기존 답변·생성 문서를 보존하고 누락 작업부터 이어갑니다. 승인안에 없던 기존 사용자 내용을 바꿔야 하면 그 차이만 먼저 확인받습니다:
1. `Ark/<맞춤방>/`, `Ark/기록-인사이트/Daily/`, `Ark/기록-인사이트/Reviews/`, `Archive/wiki/<맞춤방>/`, `Outputs/블로그/`, `Outputs/카드뉴스/` 폴더 생성 (`Ark/Blocks/`는 유지)
2. `0_Me/Purpose-L1L2L3.md` 생성 (5규약 `type: me` + `L1 인생 목표 · L2 올해 역할 표 · L3 이번 분기 프로젝트 표` 구조로 직접 생성)
3. `0_Me/My-Knowledge-Domain.md` 생성 (5규약 `type: me` + `0단계 프라이밍 · 1단계 3~5개 지식영역+태그` 구조로 직접 생성)
4. `0_Me/5S-자가진단-YYYY-MM-DD.md` 생성 (`_TEMPLATES_/5S-자가진단 워크시트.md` 기반으로 `{{date:YYYY-MM-DD}}`를 실제 날짜로 치환하고 `status: organized` 및 4번 질문 결과 기록)
5. `0_Me/_FRONTMATTER_REGS.md`의 `나의 주제 태그 목록`을 조원의 확정 태그 3~5개로 교체 (단, 시스템 원장·회고용 `record`와 `Archive/raw/`용 `raw` 기본 허용은 유지)
6. `Archive/wiki/index.md`에 확정된 3~5개 카테고리 섹션(`## 1. ...`) 및 1줄 설명 초기화
7. `Lab/Projects/<첫 프로젝트명>.md` 생성 (`_TEMPLATES_/Template_Project.md` 기반으로 `{{date:YYYY-MM-DD}}`를 실제 날짜로 치환해 승인된 첫 프로젝트 1개 자동 생성)
8. `AGENTS.md`·`GEMINI.md`·`CLAUDE.md` §1에 승인한 개인화 문구를 반영합니다. 새 말투와 충돌하는 기존 표현은 승인한 문구로 갱신해 중복을 없앱니다. 정확성·불확실성 표시 등 보호 규칙과 §0 시작·재개 규칙을 유지합니다. 세 파일에 동일한 내용을 써서 해시를 일치시킵니다.
9. `Archive/log.md`에 `## [YYYY-MM-DD HH:MM] init | [사용자명] 맞춤형 온보딩 완료` 기록 (재시도 시 같은 완료 로그를 중복 추가하지 않음)
10. 생성·갱신된 파일을 재읽어 날짜 치환·경로·세 규칙 파일 해시·로그를 검증한 뒤 `0_Me/ONBOARDING_STATUS.md`를 `completed: true`, `user_name`, `track: track-a`, `domain_tags`, `guide_stage: stage-1`로 갱신합니다. 인터뷰 답변·승인 제안은 보존하고, 아래 5절의 분기에 따라 **실제로 제시하는 다음 질문**과 `guide_step`을 함께 저장합니다. *(Stage 0 완료본이 없으면 `"Stage 0 미완료 — 필요 시 Part 1~3 워밍업 가능"` 병기)*

### 5. 다음 단계 순차 코칭 연결 (끊김 방지)
완료 보고 후, 개념 설명을 길게 늘어놓지 말고 조원의 상태에 맞춰 **순차 진행 1순위**를 먼저 제안합니다:
- **`0_Me/Before-Diagnosis.md`가 완료본(`status: organized`)인 경우:**
  `guide_step: Stage 1 완료 (다음: Stage 2 - 1번 JIT /ingest)`로 저장하고 묻습니다: *"Part 4~5의 폴더와 규약 세팅까지 마쳤습니다. 이제 Part 6에서 외부 자료 한 건을 정리해 보겠습니다. 지금 공부나 프로젝트에 쓸 자료 한 건의 링크·본문·파일 경로를 알려주시겠어요?"*
- **Stage 0 진단이 없거나 초안(`status: draft`)인 경우:**
  `guide_step: Stage 1 완료 (다음: Stage 0 보충 / Stage 2 선택 대기)`로 저장하고 묻습니다: *"Part 4~5의 폴더 세팅을 마쳤습니다. Part 1~3 진단의 남은 문항을 이어서 할까요, 아니면 Part 6의 자료 한 건 정리부터 할까요?"* 선택을 받으면 이 질문은 완료 처리하고, 기존 초안과 답변을 보존한 채 해당 진도·다음 질문을 저장합니다. Stage 0 선택 시 이 선택 질문의 복귀 기록은 만들지 않으며, 보충 완료 후 Stage 2로 이어갑니다.

- ❌ `AGENTS.md`, `GEMINI.md`, `CLAUDE.md` 중 일부만 수정하고 나머지 누락하기
- ❌ 한 번에 10개가 넘는 방을 만들어 2레벨 단순성 깨기
