# query — AI 백과사전(`Archive/wiki/`)에 묻고 빈틈 찾기

> **핵심 원칙:** 답은 위키와 원본 근거에서 찾고, **모르는 것은 모른다고 밝히며**, 출처를 섞지 않습니다.

## ⚙️ 경로 설정 (`Kobot-AI-OS-Starter`)

| 이름 | 설정값 | 역할 |
|---|---|---|
| `WIKI_INDEX` | `Archive/wiki/index.md` | **L1 진입점** — 가장 먼저 읽는 카탈로그 |
| `WIKI_DIR` | `Archive/wiki/` | **L2** — AI 컴파일 위키 |
| `RAW_DIR` | `Archive/raw/` | **L3** — 불변 원본 (정확한 수치·원문 확인 시만 진입) |
| `WIKI_LOG` | `Archive/log.md` | 작업 원장 (`query`는 환류 여부와 무관하게 항상 기록) |
| `BLOCKS_DIR` | `Ark/Blocks/` | **L4 (명시 요청 시)** — 수확된 내 원자 지식 |
| `TOPICS_DIR` | `Ark/` | **L4 (명시 요청 시)** — 내 공부·생각 노트 |
| `OUTPUT_DIR` | `Outputs/` | 외부 공유·팀 배포·포트폴리오 최종 산출물 출구 |
| `EXCLUDE` | `_TEMPLATES_/`, `_BOT_PACK_/`, `.agents/`, `Welcome/`, `AGENTS.md`, `GEMINI.md` | 검색 제외 대상 |
| `PAGE_CAP` | `15` | 초기 위키 권장 상한 |

## 에이전트 실행 절차

### 0. 사전 점검 (L1 + 실제 파일 목록 대조)
1. `Archive/wiki/index.md` 읽기
2. `Archive/wiki/` 하위 카테고리의 실제 `.md` 파일 목록 확인 (`AGENTS.md`, `index.md` 제외)
   - 만약 `index.md`에 빠진 고아 페이지가 있거나 숫자가 어긋나면, 검색에는 실제 파일까지 포함하되 답변 끝에 `/lint` 점검을 권고합니다.

### 1. 3계층 드릴다운 탐색 (+ L4 선택)
- **L1 (`Archive/wiki/index.md`):** 제목·1줄 요약만 보고 후보 페이지 식별. L1만으로 충분하면 L2 미진입.
- **L2 (`Archive/wiki/<카테고리>/`):** 관련 위키 페이지 **최대 3개** 열람. (`## 다른 관점 / 모순`과 `⚡` 표시 반드시 포함 확인)
- **L3 (`Archive/raw/`):** 정확한 수치·원문 인용이 필요할 때만 확인 (읽기 전용).
- **L4 (`Ark/Blocks/` → `Ark/`):** 사용자가 *"내 생각도 같이 봐줘"*라고 **명시 요청**한 경우에만 확장 검색.

### 1-B. 백지 상태 (역질문 빈틈 코칭) 모드 (선택)
사용자가 *"뭐부터 써야 할지 막막하다 / 내 이해도를 질문으로 먼저 테스트해 줘"*처럼 요청하면, 정답을 바로 쏟아내지 않고 아래 순서를 따릅니다:
1. 위키(`L2`)·원본(`L3`) 근거로 **핵심 진단 질문 3~4개**만 먼저 던집니다. (사용자가 1줄씩 편하게 답하거나 모르면 *"모름"*이라고 답해도 됨을 안내)
2. 사용자의 답변을 받은 뒤 **① 정확히 맞힌 부분 ② 기존에 알던 유사 개념과 뒤섞인 오개념 ③ 초보자 눈높이 일상 비유 교정** 순으로 답변을 합성합니다.
3. 말로만 와닿기 어려운 물리·구조·파형 개념이면 인터랙티브 HTML 시뮬레이터나 도식 제작을 함께 제안합니다.

### 2. 답변 합성 (결론부터 · 출처 태그 엄격 분리)
- **`[wiki]`**: `Archive/wiki/` 페이지 근거
- **`[raw]`**: `Archive/raw/` 불변 원본 직접 인용
- **`[💡 내 지식]`**: `Ark/Blocks/` 또는 `Ark/` (L4 명시 검색 시)
- **`[일반 지식]`**: 위키 밖에 있는 배경지식 (**반드시 별도 표기, 위키 근거처럼 포장 금지**)

위키에 없는 내용은 **"현재 위키에 해당 근거가 없다"**고 분명히 보고합니다.

### 3. 답변 후 처리 (휘발 방지 · 필요 시 1회 확인)
- 단순 1회성 확인은 대화로 끝내고 `Archive/log.md`에만 남깁니다.
- **내 생각 고정 (`Ark/`):** 질문·코칭 과정에서 새로 깨달았거나 바로잡은 핵심 개념이 있으면 *"방금 바로잡은 핵심 1가지를 `/brain-add-seed`로 `Ark/`에 심거나 `Daily-Reflect`에 남길까요?"*라고 1줄 제안합니다.
- **위키 환류 / 산출물 연결:** 재사용 가치가 있는 분석은 승인 후 `Archive/wiki/<카테고리>/` 편입(`🔄` 마크) 또는 팀 배포·발표용 완성본은 루트 `Outputs/`로 연결합니다.

### 4. `Archive/log.md` 기록 (항상 기록)
```markdown
## [YYYY-MM-DD HH:MM] query | 질문 요약
- **질문:** "[질문 핵심]"
- **탐색 깊이:** L1 → L2 N페이지 (L3 진입 여부)
- **참조:** [[Archive/wiki/...]] (없으면 "없음")
- **미수록:** [위키에 없던 빈칸 — 다음 `/ingest` 후보]
- **환류:** [[Archive/wiki/...]] 또는 (환류 안 함)
```

## 절대 하지 않는 것
- ❌ 위키 출처 없이 일반 지식을 `[wiki]`인 것처럼 섞어 답하기
- ❌ 파일 존재를 확인하지 않고 가짜 `[[wikilink]]` 지어내기
- ❌ `## 다른 관점 / 모순`을 빼고 한쪽 주장만 단정해 답하기
- ❌ 사용자 승인 없이 `Archive/wiki/`에 답변 무단 저장하기
- ❌ `Archive/output/` 같은 미존재 폴더에 저장하기 (산출물은 루트 `Outputs/`)
- ❌ `Archive/log.md` 기록 누락하기 · `Archive/raw/` 수정하기
