# Archive/AGENTS.md — AI 백과사전(LLM Wiki) 운영 규약

이 폴더(`Archive/`)는 Karpathy의 **LLM Wiki** 패턴을 적용한 공간입니다.

## 1. 구조 & 불변성
- **`raw/` (불변 원본):** 외부 자료 보관소 (`강의노트/`, `데이터시트-논문/`, `아티클/`, `도서/`, `assets/`). **원문 본문·비문서 파일은 수정·요약 덮어쓰기·삭제하지 않습니다.** 외부 폴더와 `Welcome/`의 외부 자료는 당장 쓸 1~2건씩 복사하며 원래 파일을 보존합니다. 같은 원본은 재사용하고 동명 다른 파일은 덮어쓰지 않습니다.
- **`wiki/` (AI 컴파일 책장):** 온보딩 시 생성한 카테고리 폴더(본인 `Ark/`와 1:1). 모든 페이지(`index.md` 포함)는 `0_Me/_FRONTMATTER_REGS.md` 5규약(`type: wiki`)을 지킵니다.
- **`log.md` (작업 원장):** 모든 `init`, `ingest`, `query`, `brain-wiki-sync`, `lint` 이력을 아래로 누적합니다.

## 2. 핵심 규칙
1. **탐색 순서:** 질의(`/query`) 시 항상 `wiki/index.md`를 먼저 읽습니다.
2. **모순 병기 & 링크 충돌 방지:** 상충되는 관점은 덮어쓰지 않고 `## 다른 관점 / 모순`에 `⚡` 표시와 함께 병기하며, 링크는 `[[Archive/wiki/<카테고리>/<파일명>|<표시제목>]]` 전체 경로를 씁니다.
3. **동시 갱신:** 위키 페이지 추가·수정 및 `/lint` 점검 시 **같은 작업 안에** `wiki/index.md`와 `log.md`를 함께 갱신합니다.
4. **산출물 출구:** 외부 공유·발표용 완성본은 `Archive/`가 아니라 루트 `Outputs/`로 내보냅니다.

## 3. 위키 작성 전 규모 점검 (정본)

- **`PAGE_CAP = 15`는 초기 실습의 권장 경고선**입니다. 모든 위키의 절대 한도나 장애 판정 기준이 아닙니다. 강의 `5.3.5`처럼 성장하면 주제별 작은 목차·위키로 나누는 방안을 검토합니다.
- `/ingest`, `/brain-wiki-sync`, `/query`의 위키 환류는 작성 전에 실제 `Archive/wiki/` 전체 `.md` 수 **N**과 이번 계획의 신규 페이지 수 **K**를 확인합니다. 모든 `index.md`·`AGENTS.md`·`.gitkeep`은 제외하고, 기존 페이지 갱신은 K에 넣지 않습니다. `index.md`의 숫자만 믿지 않습니다.
- **K > 0이고 N + K가 경고선 이상이면** 신규 작성 전에 `/lint` 진단과 기존 보강·병합·주제별 목차 분리·신규 계획을 함께 제시합니다. 사용자가 선택한 계획만 실행하며, 이미 같은 점검 결과와 대상을 승인했다면 승인을 반복해서 묻지 않습니다. 계획·대상·페이지 수가 바뀌면 다시 확인합니다. 자동 삭제·병합·분할은 하지 않습니다.
- 조회·진단과 **K = 0인 기존 페이지 갱신은 페이지 수만으로 차단하지 않습니다.** 경고선 미만의 신규 작성도 각 스킬의 구조 승인 규칙을 따릅니다. 작성 후 실제 페이지·목차·로그를 함께 확인합니다.

## 4. 원본 등록·처리 상태·위치 정리

- 등록 시 **수신한 Markdown 사본에만** `type: raw`, `created`, `tags`, `status: unread`, `source`를 기입·정리할 수 있습니다. 원래 파일과 본문은 그대로 보존합니다. 비문서 파일이나 원형 보존이 필요한 파일에는 frontmatter를 억지로 넣지 않습니다.
- `/ingest`는 위키·목차·로그 저장을 재읽어 확인한 뒤에만 관리 중인 raw Markdown의 **`status: unread → ingested`**를 갱신합니다. 원형을 유지한 파일의 처리 여부는 로그에 남깁니다. 이것이 등록 후 메타데이터 변경의 예외이며, 본문 수정 허용이 아닙니다. 실패 시 완료로 표시하지 않습니다.
- **이동은 ingest의 기본 동작이 아닙니다.** 승인받은 볼트 내부 정리에서는 이동 전 볼트 내 전체 인바운드 링크와 본문/파일 해시를 확인하고, 이동·링크 교정·목차/로그 갱신을 한 작업으로 실행합니다. 다른 raw 본문이나 승인 범위 밖 파일의 링크를 고쳐야 한다면 이동을 보류하고 원래 경로를 유지한 복사안을 제안합니다. 완료 후 링크 해소와 본문 보존을 확인합니다. 외부 원본은 이동하지 않습니다.
- `Welcome/`의 개인 생각은 raw로 보내지 않고 `/brain-add-seed`로 연결합니다. 자료와 생각이 섞였거나 성격이 불명확하면 먼저 확인합니다.
